# 原生小程序首页分类展示设计

## 背景

原生小程序首页当前只取前 8 个分类，并且分类数量只统计 `ready` 工具。完整注册表中大量工具处于 `adapting` 或 `desktop-only` 状态，因此用户会看到多个分类数量为 0；首页还会在分类下方重复展示“常用工具”。

## 目标

1. 首页展示注册表中的全部分类，保持 `NATIVE_CATEGORIES` 的既有顺序。
2. 分类数量统计该分类下全部已登记工具，不因适配状态显示为 0。
3. 首页无搜索词时只展示分类入口，不再展示常用工具卡片；有搜索词时继续展示搜索结果。

## 方案

在工具注册表增加统一的分类摘要函数，返回分类定义和全部工具数量。首页直接消费该摘要，避免页面自行切片或重复实现统计逻辑。分类入口从横向滚动标签调整为两列分类卡片，卡片显示分类名称、简介和工具数量；点击行为仍跳转到现有分类页。

## 边界

- 不改变工具状态、工具路由、搜索过滤或分类页行为。
- 不新增股票入口、个人项目、登录或 WebView。
- `desktop-only` 工具仍可计入分类总数，但其详情页继续显示能力限制。

## 验收标准

- `getNativeCategorySummaries()` 返回的分类数等于 `NATIVE_CATEGORIES` 数量。
- PDF、音频等原先显示 0 的分类数量大于 0，并包含所有状态的登记工具。
- 首页源码不再包含 `featuredTools`、`slice(0, 8)` 或“常用工具”展示区。
- 全量测试、lint 和小程序 TypeScript 编译通过。
