# 逐梦工具箱原生小程序工具迁移设计

## 背景

当前 `xiaochengxu` 是一个使用 `<web-view>` 打开 `https://zhumenggy.top/?mini=1` 的小程序壳。个人主体小程序没有业务域名能力，因此这套方案只能在开发者工具中调试，不能作为正式发布方案。网站端 `SD` 继续保留，原生小程序需要在 `xiaochengxu/miniprogram/` 内独立实现。

当前网站工具注册表位于 `SD/tools/registry.tsx`，包含 233 个工具定义，覆盖 PDF、图片、格式转换、开发者、计算器、趣味、测评、塔罗星座、鼠标、文档、音频、视频、数据、办公、学术、文本和站长工具等分类。

## 目标

将现有工具中能够在手机微信环境完成的功能迁移为原生微信小程序页面和逻辑，形成不依赖 WebView 的个人主体版本，并保持网站端功能不受影响。

原生小程序需要具备：

- 原生首页、分类、搜索和工具详情页；
- 统一的工具卡片、输入区、操作按钮、结果区和错误提示；
- 本地计算、文本、编码、文件、图片和 PDF 能力的原生适配；
- 对确实需要线上服务的功能使用 `wx.request` 调用公开 HTTPS 接口；
- 分包加载重型能力，避免首页启动时加载全部库；
- 可在微信开发者工具、真机预览和个人主体发布流程中独立验证。

## 不在范围内

- 股票入口；
- 个人项目、研报中心、登录管理、独立工作区及其他网站项目页面；
- 依赖真实鼠标的 CPS、DPI、鼠标按键、滚轮、鼠标轨迹、轮询率等工具；
- 依赖桌面文件夹、浏览器扩展、系统级剪贴板或无法由微信 API 替代的桌面权限；
- 将网站 React 组件直接嵌入小程序；
- 在小程序中保存用户账号、建立个人中心或同步网站历史记录。

无法保持原功能的工具不伪装成可用工具，而是在原生工具注册表中标记为不支持，并在需要时显示“请在网站电脑版使用”说明。

## 方案选择

### 方案 A：统一工具容器 + 原生工具组件（采用）

首页、分类页和工具页使用统一页面框架，每个工具实现为一个职责独立的原生组件。工具注册表保存名称、分类、能力、路由和组件标识，工具页根据工具 ID 选择对应组件。

优点是公共交互只实现一次，工具可以独立迁移、测试和分包，新增工具不会复制整套页面。WXML 不依赖 React 的动态组件机制；工具容器通过静态组件分支和分包路由表完成可预测加载。

### 方案 B：每个工具独立一个小程序页面

隔离性较好，但需要维护大量页面配置、公共布局和路由，工具数量增长后容易出现标题、返回、错误提示和样式不一致，因此不采用。

### 方案 C：原生页面加 WebView 兜底

可以减少迁移量，但个人主体正式版仍然受业务域名限制，无法解决当前核心问题，因此不采用。

## 用户界面

### 首页

- 使用现有小程序工具版的暖色背景、棕色主按钮、绿色/棕色图标渐变和圆角卡片；
- 顶部显示“逐梦工具箱”和简短说明；
- 提供工具搜索框；
- 分类使用横向可滚动标签；
- 工具卡片采用手机双列布局，窄屏自动变为单列；
- 股票和个人项目不显示；
- 不加入广告、登录入口或网站端项目入口。

### 分类页

- 显示分类名称、工具数量和分类描述；
- 支持按名称、描述和标签搜索；
- 工具卡片显示图标、名称、简介和能力标识；
- 不支持手机运行的工具不进入可用列表，必要时在“桌面端工具”说明中列出。

### 工具页

- 顶部返回按钮、工具名称和简短说明；
- 输入区根据工具类型使用文本框、选择器、日期选择、文件选择、图片选择、相机或录音控件；
- 主操作按钮始终有明确动词，例如“格式化”“计算”“开始处理”“生成”；
- 结果区支持复制、清空、重新处理、保存或打开；
- 处理中禁用重复提交并显示进度或加载状态；
- 页面离开前不强制保存，必要的草稿使用本地缓存。

## 技术架构

原生小程序与网站代码分离，目标目录结构如下：

```text
xiaochengxu/miniprogram/
├─ app.ts / app.json / app.wxss
├─ pages/
│  ├─ home/                 首页
│  ├─ category/             分类页
│  └─ tool/                 核心工具容器
├─ components/
│  ├─ common/               搜索、卡片、按钮、结果面板
│  └─ tools/                轻量原生工具组件
├─ packages/                PDF、图片、办公等重型分包
├─ data/
│  ├─ toolRegistry.ts       原生工具注册表
│  └─ categories.ts         分类元数据
├─ services/
│  ├─ http.ts               wx.request 统一封装
│  ├─ file.ts               文件选择、读取、保存和打开
│  └─ storage.ts            本地缓存封装
└─ utils/                   纯计算、格式化和校验逻辑
```

`xiaochengxu/miniprogram/data/toolRegistry.ts` 不直接引用 React 或 `SD/tools/registry.tsx`。它使用原生类型描述工具：

```ts
type NativeToolCapability = 'local' | 'request' | 'file' | 'camera' | 'audio' | 'unsupported';

interface NativeToolDefinition {
  id: string;
  name: string;
  description: string;
  category: string;
  icon: string;
  capability: NativeToolCapability;
  route: string;
  status: 'ready' | 'adapting' | 'desktop-only';
}
```

页面负责状态和布局，工具组件负责交互，`utils` 负责纯逻辑，`services` 负责微信平台 API。这样可以让纯逻辑在 Node/Vitest 中测试，也可以替换平台适配而不修改计算代码。

## 数据流和平台适配

### 本地工具

文本、JSON、编码、计算器、随机工具、测评评分和塔罗结果等功能不联网。输入进入工具组件，调用 `utils` 中的纯函数，结果留在当前页面；需要保留草稿时通过 `storage.ts` 使用 `wx.setStorageSync`。

### 文件和图片工具

通过 `file.ts` 统一处理 `wx.chooseMessageFile`、图片选择、文件读取、临时文件路径、Canvas 转换和文件打开。每个工具明确显示本地处理或上传处理，默认不上传用户文件。需要保存到相册或文件时，先申请对应权限并提供失败重试。

### 后端工具

`http.ts` 统一封装 HTTPS 请求、超时、错误码和重试。公开服务基址使用 `https://zhumenggy.top`，不使用 `localhost`、局域网 IP、8000/8012 等内部端口，也不把密钥放到小程序包内。实际迁移某个工具时，只有确实需要原生上传或下载，才增加相应服务器域名配置。

### 不支持能力

工具注册表将桌面鼠标、浏览器扩展、系统文件夹等能力标记为 `desktop-only`。首页默认不把它们作为可用工具展示；从搜索或旧链接进入时显示原因和网站电脑版入口提示。

## 分包与迁移顺序

迁移按可验证批次执行，每批都能独立编译和测试：

1. 原生首页、分类、搜索、工具容器和公共组件；
2. 开发者工具、计算器、文本工具和随机工具；
3. 测评、塔罗和星座工具；
4. 图片、格式转换、数据、办公和学术工具；
5. PDF、文档、音频、视频和站长工具；
6. 对所有桌面专用工具完成隐藏或兼容性说明。

PDF、OCR、图片增强、办公文档等重型依赖放在分包。主包只保留首页、公共组件、工具元数据和第一批轻量工具；分包按分类或能力边界组织，避免首页启动时解析全部依赖。

## 异常、隐私和权限

- 输入为空、格式错误和参数越界在页面内即时提示；
- 文件过大、类型不支持、读取失败和保存失败显示具体原因及重试入口；
- 接口超时保留用户输入，提供重新请求；
- 用户拒绝相机、相册、麦克风或文件权限时，说明权限用途并提供重新授权入口；
- 不在小程序端保存 AppSecret、第三方 API Key 或用户身份凭据；
- 处理结果默认只存在当前页面或本地临时文件，离开页面后不建立账号历史；
- 任何需要上传的工具在操作前显示上传提示，接口失败时不清除原文件和输入。

## 测试和验收

### 自动化测试

- 纯逻辑函数使用 Vitest 覆盖正常值、空值、边界值和非法输入；
- 工具注册表测试每个可用工具都有名称、分类、路由、能力和对应组件；
- 路由契约测试首页、分类和工具 ID 均能解析；
- 分包契约测试不允许主包直接引用重型分包文件；
- TypeScript 检查使用 `xiaochengxu/tsconfig.json` 和微信小程序类型定义。

### 微信环境测试

- 微信开发者工具编译和预览；
- Android/iOS 真机打开首页、搜索、分类和工具页；
- 文件选择、相机/相册权限、保存和打开文件；
- 断网、接口超时、服务端错误和重复提交；
- 窄屏、长文本、横竖屏切换和低端设备滚动；
- 关闭“不校验合法域名”后验证原生请求域名；
- 个人主体发布前确认不再依赖 `web-view` 或业务域名。

## 发布要求

- 小程序只使用原生页面和组件；
- 个人主体不配置也不依赖业务域名；
- 需要请求后端时，在小程序后台配置 `https://zhumenggy.top` 的 request 合法域名；
- 线上接口必须使用 HTTPS，并通过网站反向代理暴露，不能暴露内部端口；
- 每个迁移批次完成自动测试、开发者工具编译和真机冒烟测试后再合并；
- 网站端继续按现有部署流程发布，小程序端单独上传和审核。

## 验收标准

当以下条件全部满足时，原生迁移版本视为完成：

1. 首页、分类、搜索和工具详情全部是原生 WXML/TypeScript，不加载网站页面；
2. 范围内工具可在个人主体小程序中编译、预览和运行；
3. 不支持手机的工具被明确隐藏或标记，不出现假可用按钮；
4. 纯本地工具在断网状态下仍能使用；
5. 需要接口的工具只通过配置好的 HTTPS request 域名访问；
6. 自动化测试、TypeScript 检查、开发者工具编译和真机冒烟测试均通过；
7. 网站端现有功能和代码不因小程序迁移而改变。
