# 工具站微信小程序 WebView 方案设计

日期：2026-09-10  
范围：`xiaochengxu` 小程序与 `SD` 工具站  
状态：已获用户确认，待实施计划

## 背景

当前微信小程序目录是官方 TypeScript 空白模板，网站 `SD` 已经包含完整的工具注册表、分类、工具详情页、股票入口和小游戏。用户希望把网站的工具界面放进微信小程序，不需要个人项目页，也不希望把所有工具逻辑重新用小程序原生组件重写。

## 目标

- 小程序能够打开线上工具站，并在微信内完成工具浏览、搜索、分类和使用。
- 复用网站现有工具逻辑，避免为几十个工具重复实现一套 WXML/TypeScript 版本。
- 网站在 `mini=1` 模式下只展示工具相关内容，隐藏个人项目、展示页、报告/管理入口和不属于工具入口的页面。
- 为移动端重新组织网站的导航、间距、卡片和工具容器，使页面适合小程序 WebView 的窄屏环境。
- 保留股票工具、通用工具和小游戏等用户希望作为工具使用的入口；不把个人项目页放进小程序首版。
- 小程序端提供加载、加载失败、重试、分享和基础导航承载逻辑。

## 非目标

- 不把整个 React 网站源码打包进小程序包。
- 不在本阶段把所有工具重写为原生小程序页面。
- 不接入微信云开发，不新增个人中心、账号体系或个人项目页。
- 不修改网站桌面端的默认信息架构和正常访问路径。
- 不承诺所有依赖浏览器高级能力的文件、摄像头、下载或第三方接口工具在 WebView 中零改动可用；这些工具按实际兼容性单独降级或适配。

## 方案与边界

### 小程序端

- 保留 TypeScript 小程序工程，使用一个主要页面承载 `<web-view>`。
- `pages/index/index` 读取固定的线上入口 `https://zhumenggy.top/?mini=1`，不请求本地开发地址。
- 页面处理 `bindload`、`binderror` 和重试状态；WebView 加载成功后不显示启动遮罩，加载失败时给出重试和检查网络提示。
- `app.ts` 不执行官方空白模板的示例日志和用户资料登录逻辑；本阶段不需要微信登录。
- 提供 `onShareAppMessage`，分享后仍进入工具模式入口。
- `app.json` 只保留实际使用的首页页面，不再把示例日志页当作产品入口。

### 网站工具模式

- 增加一个可测试的 `isMiniMode` 判断：首次通过 `?mini=1` 进入时记录当前会话，网站内部路由继续保持工具模式，不要求每个链接手工拼接参数。
- 工具模式使用独立的轻量首页/布局，直接突出搜索、分类和工具入口，不复用包含个人项目展示的完整桌面首页。
- 工具模式允许访问工具详情路由、工具分类、股票工具和小游戏；个人项目页、研报展示页、登录管理页和独立工作区不出现在工具模式导航中。
- 工具模式下直接访问被隐藏的个人项目/报告/管理路由时，统一返回工具模式首页或显示“该页面不在小程序工具版中”，不能通过手工改 URL 绕过入口限制。
- 工具详情继续使用已有 `ToolWindow` 和工具注册表，避免复制组件实现；需要兼容的 API 仍使用现有线上后端路径。
- 桌面端继续使用现有 `AppLayout`；只有检测到工具模式时才切换移动端布局和导航样式。

股票页面目前是独立的前端入口，不完全属于 `SD` React 路由。首版保留它的工具入口并确保链接可从 WebView 打开；如果该独立前端需要专用的微信窄屏布局，再在同一套 `mini=1` 约定下补充适配，不把它与主工具站的模式判断混在一起。

### 移动端适配

- 新增工具模式样式类，处理安全区、顶部标题、分类横向滚动、搜索框、双列/单列工具卡片和工具内容区宽度。
- 隐藏侧边目录、个人项目画廊、报告推广卡片和桌面端专属留白。
- 工具页保留返回入口、标题、描述、主要操作和结果反馈；复杂工具在窄屏下改为纵向布局。
- 不使用会依赖桌面鼠标悬停才能理解的交互；对鼠标测试等明显桌面专用功能显示兼容性提示，而不是让页面无响应。

## 数据和错误处理

- 网站工具逻辑仍在 WebView 中执行；小程序只负责载入网页，不复制工具状态。
- 小程序网络错误显示可重试状态，不伪造成功结果。
- 工具端已有 API 失败提示继续沿用；需要后端的工具必须通过线上 HTTPS 地址访问，不能使用本地端口或 `localhost`。
- 文件选择、下载、剪贴板、摄像头等能力按 WebView 实际支持情况检测；不可用时给出明确提示，并把原生微信适配留作后续独立任务。

## 测试与验收

### 网站自动化验证

- `isMiniMode` 在入口参数、会话保持和普通网站访问三种场景下行为明确。
- 工具模式渲染搜索、分类、工具卡片，并且不渲染个人项目/报告入口。
- 工具详情路由在工具模式下仍能找到工具标题、返回入口和主要交互。
- 桌面端现有页面测试和工具注册表测试继续通过。

### 小程序工程验证

- TypeScript 编译通过，`app.json` 页面路径存在。
- 微信开发者工具中加载成功时能打开线上工具入口，加载失败时能点击重试。
- 真机/预览环境使用 HTTPS 域名；上线前在小程序后台配置并校验 WebView 业务域名。

### 验收标准

- 打开小程序后进入的是工具首页，不出现个人项目展示。
- 能从小程序内完成工具搜索、分类浏览、打开工具、返回和再次打开其他工具。
- 网站桌面端正常访问不受 `mini=1` 模式影响。
- 典型文本、计算器、编码、图片/二维码等工具在移动布局中可操作；不兼容的高级文件能力有明确提示。
- `SD` 的 lint、测试和构建，以及小程序 TypeScript 检查全部通过。
