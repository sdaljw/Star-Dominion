# 云端 JY901S 预警设置设计

## 目标

在 STM32 监测台的 UM980 数据卡片中增加第八个“预警设置”格。用户可以配置 JY901S 加速度 X/Y 和三轴姿态角 X/Y/Z 的阈值；阈值由服务器统一保存，云端根据设备上传的 IMU 数据计算报警，使所有打开网页的用户和所有设备使用同一套标准。

## 已确认的行为

- 五个指标分别配置：加速度 X、加速度 Y、姿态角 X、姿态角 Y、姿态角 Z。
- 任意一个已启用指标达到或超过阈值即触发报警（OR 逻辑）。
- 判断使用绝对值：例如 `-0.85 g` 会触发 `0.8 g`，`-31°` 会触发 `30°`。
- 空值表示关闭该项；默认五项均为空，不产生云端报警。
- 当前值回到阈值以下后自动消警。
- 配置是全站统一的服务器配置，不按浏览器、用户或设备分开保存。
- 设备上传的旧 `ALARM:` 报文不再决定报警状态，只保留在原始消息日志中兼容查看。

## 方案选择

### 采用：后端 JSON 配置文件 + Flask 接口 + 后端实时计算

现有 STM32 服务已经由 `4G.py` 维护设备状态，并通过 `/data` 和 WebSocket 向多个网页推送快照。增加一个小型 JSON 配置文件即可满足全站持久化需求，不引入数据库迁移，也不会让浏览器各自保存不同标准。

配置文件默认放在后端脚本所在目录的 `alarm_settings.json`，也支持用 `STM32_ALARM_SETTINGS_PATH` 指定绝对路径。保存时先写临时文件，再用原子替换覆盖正式文件；文件不存在、内容损坏或字段无效时回退到五项均为空的安全默认值。

SQLite 是更重的替代方案，适合未来需要审计历史、多个配置版本或细粒度权限时再引入。浏览器 `localStorage` 不符合“所有用户共用标准”，因此不采用。

## 后端数据模型

配置文件和接口使用以下字段，数值单位与设备报文一致：

```json
{
  "acc_x": null,
  "acc_y": null,
  "angle_x": null,
  "angle_y": null,
  "angle_z": null,
  "updated_at_ms": 0
}
```

阈值必须是有限的非负数；`null` 表示禁用。`updated_at_ms` 由服务器写入，用于页面确认最后保存时间，不参与报警判断。

服务端新增接口：

- `GET /alarm-settings` 返回 `{ "settings": <配置>, "updated_at_ms": <时间> }`。
- `PUT /alarm-settings` 接收五个字段，校验通过后持久化并返回最新配置；字段缺失按 `null` 处理，非法负数、非数字和无穷值返回 `400`。

接口沿用当前 STM32 服务的同源代理和访问模型。保存成功后立即用当前设备缓存重新计算报警，并向现有 WebSocket 客户端广播新快照。

## 云端报警计算

`apply_device_message` 在合并新的 `ACC` 或 `ANGLE` 数据后调用独立的云端评估函数。评估读取当前设备的 `imu.acc` 和 `imu.angle`，只检查已配置且已有有效数据的指标：

```text
触发条件 = 任一 enabled_threshold <= abs(current_imu_value)
```

活动报警统一使用 `state['alarm']`，并包含来源和触发细节，示例：

```json
{
  "level": "RED",
  "source": "cloud",
  "metric": "acc_x",
  "label": "加速度 X",
  "value": -0.85,
  "absolute_value": 0.85,
  "threshold": 0.8,
  "message": "加速度 X 达到 0.850 g，阈值 0.800 g",
  "triggered_at_ms": 1770000000000
}
```

如果同时超过多个指标，`alarm.conditions` 保存全部触发项，`metric` 和 `message` 使用第一个触发项作为摘要。没有任何指标超限时将 `alarm` 设为 `null`。设备最后一次有效数据超过现有 5 秒在线窗口后，报警也不继续显示为活动状态，避免用过期数据持续报警。

服务端收到旧格式 `ALARM:` 时仍允许写入原始消息列表，但不再调用它更新 `state['alarm']`；因此报警唯一来源是服务器根据 IMU 缓存和全局配置计算出的结果。

## 前端交互

`Um980Panel` 保持四列网格：现有七个指标占据前两行的前七格，第八格增加“预警设置”。该格显示：

- 未配置时：`未启用`。
- 配置后：`已启用 n 项`。
- 有云端报警时：使用红色状态提示并显示触发指标摘要。

点击第八格打开紧凑的设置弹层，不增加左侧面板高度，不引入滚动延伸。弹层包含五个数字输入框、单位提示、取消和保存按钮：

- 加速度 X/Y：单位 `g`，允许小数，最小值 `0`。
- 姿态角 X/Y/Z：单位 `°`，允许小数，最小值 `0`。
- 清空输入即保存为 `null`，关闭该指标。

页面加载时从 `GET /alarm-settings` 读取统一配置；保存通过 `PUT /alarm-settings`，成功后更新卡片状态并提示“云端预警标准已保存”。不使用 `localStorage`，也不在前端自行判断报警，前端只展示后端快照中的云端结果。请求失败时保留当前已加载配置并提示保存失败，不伪造成功状态。

现有右侧通知面板继续负责显示报警通知；通知内容改为使用云端报警的 `label`、当前绝对值和阈值。报警恢复时清除对应的去重签名，下一次重新超限可以再次通知。

## 文件边界

主网站：

- `4G/4G.py`：配置加载/保存、接口、云端评估和快照。
- `4G/tests/test_4g_message_filter.py`：后端配置、评估和旧报警忽略测试。
- `SD/pages/stm32/types.ts`：配置和云端报警类型。
- `SD/pages/stm32/telemetry.ts`：快照归一化。
- `SD/pages/stm32/Um980Panel.tsx`：第八格和设置弹层。
- `SD/pages/Stm32Window.tsx`：读取/保存配置、通知和组件参数。
- `SD/pages/stm32/telemetry.test.ts`、`SD/lib/integrationRoutes.test.ts`：前端行为与结构回归。

可移植的 `wangye/` 模块同步相同的后端和 STM32 前端改动，保证以后从移植包重新部署时不会恢复旧逻辑；README 补充配置接口和持久化说明。

## 验证范围

后端测试覆盖：

1. 默认配置为空且可从文件加载。
2. `PUT` 接口接受有限非负数和 `null`，拒绝非法值。
3. 任意一个加速度或姿态角绝对值达到阈值触发报警。
4. 所有已启用指标低于阈值后自动消警。
5. 多项同时超限时保留全部触发条件。
6. 配置保存后重新加载仍保持标准。
7. 设备 `ALARM:` 报文不再覆盖云端报警。
8. 离线/过期数据不会保持活动报警。

前端测试覆盖：

1. 第八格存在且不破坏四列紧凑布局。
2. 五个输入字段、单位、空值禁用和保存状态正确显示。
3. 页面通过服务器接口加载/保存，不使用 `localStorage`。
4. 云端报警和恢复通知使用新字段。
